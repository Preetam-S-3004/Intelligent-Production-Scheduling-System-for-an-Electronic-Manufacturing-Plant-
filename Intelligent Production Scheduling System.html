Intelligent Production Scheduling System

Alliance School of Advanced Computing micro-project. Orders move through assembly, soldering, testing, calibration and inspection on a shared set of machines. Switch schedulers, add an urgent order, or turn failures and maintenance on and off, and watch the plan change.

Where each data structure is used

Array

Machine table, the operations inside each order, the Gantt table (machine by time), and the temporary list of ready operations that gets sorted.

Singly linked list

The master list of production orders. New and urgent orders are appended at the tail in constant time.

Queue (linked list)

One waiting queue per operation type, plus a separate urgent queue. A machine takes from the urgent queue first, then the normal queue.

Stack (linked list)

Operation history. When a machine fails, records are popped to find the interrupted operation, which is removed and sent back to the front of its queue.

Sorting and searching

Insertion sort orders ready operations by urgency, priority, deadline, then duration. Linear search finds free machines and orders; binary search works on a sorted ID array.

Limitations and how the design handles them

  • Greedy, not optimal. Job shop scheduling is NP-hard, so the plan is good but not guaranteed best. The comparison table shows the gain over first come, first served.
  • Fixed processing times. Durations are known in advance. Random delays are a natural next step.
  • Failed work restarts. An interrupted operation loses its progress and resumes first in line once a machine is free.
  • Fixed-size arrays. The plant has a known number of machines and five operation types, so arrays suit it. Overflow is checked on input.
  • No setup or transport time. Listed as future work.
  • Invalid input. Circular dependencies are caught with a stack before scheduling starts.
